# Тусовка

Сервіс подій з обмеженою кількістю місць: реєстрація, публічні та приватні тусовки, RSVP «Іду», коментарі.

Час зберігається в UTC і показується за київським поясом (`Europe/Kyiv`).

## Швидкий старт

Потрібні **Node.js 20.9+** і npm.

```bash
npm install
npm run dev
```

Відкрийте [http://localhost:3000](http://localhost:3000).

`npm install` сам створить `.env` із `.env.example`, якщо файлу ще немає, і згенерує Prisma-клієнт.
`npm run dev` застосує міграції SQLite і підніме сервер на порт 3000.

Опційно заповніть демо-дані (в іншому терміналі, поки працює `npm run dev`):

```bash
npm run db:seed
```

Демо-акаунти (лише для локальної перевірки):

- `olena@example.com` / `correcthorsebatterystaple`
- `maksym@example.com` / `correcthorsebatterystaple`

## Змінні середовища

Див. `.env.example`. Копіювати вручну не обовʼязково: скрипти зроблять це самі.

| Змінна | Призначення |
| --- | --- |
| `DATABASE_URL` | SQLite. Шлях відносно каталогу `prisma/` |
| `SESSION_COOKIE_SECURE` | `true` на HTTPS, щоб cookie отримала `Secure` |
| `APP_ORIGIN` | Публічний origin (посилання-запрошення й перевірка Origin) |

Файл `.env` не комітиться. У production (`NODE_ENV=production`) сесійна cookie ставиться з `Secure`, якщо не вимкнути це явно.

Перед продакшеном у `.env` поставте свій `APP_ORIGIN` і `SESSION_COOKIE_SECURE=true`.

## Можливості

1. Реєстрація / вхід / вихід (email + пароль).
2. Створення події: назва, опис, дата й час, місця, обкладинка, публічна/приватна.
3. Головна: майбутні публічні події, пошук за назвою (без урахування регістру, зокрема кирилиця).
4. Сторінка події: «Іду» / «Скасувати», лічильник місць, коментарі.
5. Автор редагує й видаляє свою подію, бачить список учасників (з email).
6. Приватні події — лише за невгадуваним посиланням `/i/<token>`.
7. Профіль: створені мною + ті, на які я записався.

## Безпека (коротко)

- Параметризований Prisma/SQL, без конкатенації запитів і без `$queryRawUnsafe`
- Коментарі й тексти як plain text (React екранує HTML), CSP + security headers, HSTS у production
- Авторизація кожної мутації на сервері. Список коментарів перевіряє той самий доступ, що й сторінка події
- Приватні події: випадковий invite-token (32 байти), 404 для чужих ID; токен не потрапляє в списки й HTML для не-авторів
- Обкладинка приватної події не віддається без сесії автора, RSVP або invite-токена
- Місткість у атомарному `INSERT … SELECT`. Зменшення місткості теж умовне: `UPDATE` проходить лише якщо поточна кількість RSVP не більша за нову місткість
- Пошук прибирає символи `%`, `_` і `\`, тож вони не працюють як шаблон LIKE
- Argon2id, нормалізація email, однакова помилка логіну
- Ліміт входу прив’язаний до email, а не до IP. Лівий `X-Forwarded-For` ігнорується (береться правий hop, який дописує проксі)
- Повернення після входу — лише внутрішній шлях: без `//`, `%`, `\` і схем
- Завантаження: magic bytes, ліміт 2 МБ, без SVG/HTML, випадкове імʼя
- CSRF: SameSite=Lax + перевірка Origin/Referer проти Host або APP_ORIGIN (без довіри до X-Forwarded-Host)
- Немає секретів у репозиторії
